# Selectel: реализация целевой модели

Дата: 2026-11-04. Целевой контракт: [модель](infrastructure-target-model.md),
[поля](infrastructure-field-mapping.md). Этот документ не подтверждает развёртывание.

## Подготовлено в текущем изменении

- Сведения несопоставленного сервера объясняют текущую причину и основания
  кандидатов: точное имя, аппаратная идентичность, публичный IP, WAN гостевой
  pfSense. Внутренний IP без подтверждённой области сети не используется.
- Ручное связывание с Device/VM: поиск по имени, просмотр пары, подписанное
  подтверждение на 10 минут. Повтор использует квитанцию; устаревшее состояние,
  недостаточные права и конфликт привязки отклоняются. Карточка не становится
  созданной Selectel. Операция не меняет IP, имя и размещение; дальнейшие сборы
  используют существующий контракт обогащения привязанной карточки.
- Вкладка глобального роутинга: роутеры, сети, подсети, статические маршруты,
  зоны/сервисы сети, VLAN, CIDR, шлюзы, next hop и UUID внешних связей.
  Связи строятся по явным ссылкам API. Несвязанные компоненты сохраняются,
  их нельзя выдавать за подключённые к роутеру. Неполный сбор сохраняет прежние
  данные с признаком неподтверждённой актуальности. `—` вместо ложного нуля,
  если список роутеров не получен успешно.
- Физические модули памяти/диски показаны как компоненты, а не как сырые словари
  под заголовками числовых полей VM.
- Read-only API `/api/plugins/netbox-sync-guard/providers/resources/v1/<account>/`
  отдаёт узлы и типизированные связи `netbox-sync.provider-resources.v1` для
  будущей карты. У каждого узла — источник, область, время и статус наблюдения;
  ссылки на Device/VM отфильтрованы правами и проверкой времени создания карточки.
  DNS-значения и выделенные IP не превращаются в связи принадлежности серверу.

## Основание схемы маршрутизации

[Официальный Global Router API](https://docs.selectel.ru/en/api/global-router/):
GET `/routers`, `/networks`, `/subnets`, `/static_routes`, `/zones`;
постраничные запросы с limit 200. Используются ссылки router_id/network_id,
а не совпадение CIDR. Это наблюдаемая конфигурация, не доказательство
доступности трафика или применимости firewall-правила.

### Уточнения после проверки 4 ноября

Ручные сопоставления оператор подтвердил как корректные. Правила поиска
кандидатов сохраняются; автоматическое принятие слабых совпадений — следующий
отдельный этап. Site остаётся площадкой, аккаунт/проект показываются отдельно.
Для пустого Primary IPv4 согласован приоритет публичного адреса, затем
внутреннего, при подтверждённом назначении интерфейсу; существующее значение
и чужие назначения сохраняются. Все адреса Selectel должны быть видны.

В текущей ветке интерфейса: роутер → сети/VLAN → раскрываемые подсети с CIDR,
шлюзом и служебными IP; поиск по имени/VLAN/адресу, в том числе попаданию IP в
подсеть. UUID и технические статусы скрыты из основного представления, ошибки
полноты и сведения без подтверждённой связи остаются видимыми. На Device/VM
добавлена компактная панель Selectel вместо технических custom fields.
Аппаратные CPU/RAM/диски разделены; VM использует штатные поля ресурсов.
Изменение видимости не удаляет значения custom fields или защитные claims.

## Удобство связывания и отвязка отдельного ресурса

Экран выбора всегда показывает исходный ресурс Selectel, аккаунт, UUID,
площадку и адреса. Найденные кандидаты доступны сразу; остальные карточки
появляются только после поиска. Карточки с привязкой Selectel любого аккаунта
исключены из выбора. Связь с ESXi/Proxmox не исключает карточку.

В сведениях связанного ресурса доступно «Удалить сопоставление». Проверка
показывает последствия: ранее существовавшая карточка сохраняется; доказанно
созданная Selectel карточка удаляется, если нет внешних зависимостей или сетевых
связей. Удаление не затрагивает другие ресурсы аккаунта и провайдера.
Маркер ручного отсоединения предотвращает автоматическое восстановление связи.
Повторное ручное связывание снимает его только после актуального подтверждения.

## Продолжение 4 ноября: native-проекция и автоматизация

Предыдущие разделы описывают границы PR134–136. В следующем изменении реализованы
автоматическое создание выделенных серверов при UUID/площадке и отсутствии
кандидатов; привязка единственного совместимого сетевого кандидата; создание VM
с известным регионом без придуманной зоны. Добавлены native-интерфейсы облачных
VM, VRF/Prefix/IP, NAT floating IP, Primary и прикреплённые диски с происхождением.
Обычная синхронизация гипервизора сохраняет Primary, принадлежащий Selectel.
