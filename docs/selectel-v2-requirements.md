# Selectel: требования и приёмка на тестовом NetBox

Основание: ТЗ пользователя от 2026-10-14. Статус: разработка, не релиз.

## Границы

- Production не обновлять, не очищать и не исправлять в этом этапе.
- Разработка локально, приёмка только на netbox-test. Очистка теста не является
  предварительным условием: сначала проверить сохранение существующих объектов.
- Тестировать весь доступный сервисному пользователю аккаунт, не выборку серверов.
- Новые ошибки при приёмке записывать в selectel-v2-issues.md; исправлять пакетом
  после прохождения согласованных сценариев, не менять код между каждым замером.

## Требуемый результат

1. Подключение сервисного пользователя: проверка аккаунта, прав и покрытия API.
   Все доступные ресурсы отражаются в NetBox. Для категории без адаптера явно
   показывать «не поддерживается», для отказа прав — «нет доступа»; не подменять
   их пустым успешным списком. Каталоги образов/flavor не выдавать за серверы.
2. Сбор должен переходить в создание/обновление native-объектов, а не только
   сохранять реестр. Различать счётчики обнаружено/связано/создано/обновлено/ошибка.
3. Двунаправленный порядок подключения: существующий ESXi/Proxmox/ручной объект
   получает Selectel-привязку; источник, добавленный после Selectel, принимает
   существующую карточку провайдера. Одна физическая машина — одна Device.
   Родитель Selectel означает принадлежность провайдеру, не вложенный Device.
4. Идентичность: account + provider native ID и подтверждённые аппаратные ID.
   Конфигурация, имена, адреса и цепочка WAN → pfSense VM → хост дают кандидатов,
   но одинаковые CPU/RAM не разрешают автоматическое объединение. Неоднозначность
   показывает ссылки, причины, различия и действие оператора.
5. Selectel — приоритетный источник полей, которыми он управляет: конфигурация,
   provider name, размещение, состояние и доступные сведения. Зафиксировать
   матрицу полей и единиц. Сборщик гипервизора не должен перезаписывать эти поля.
   Ошибка/отсутствие права не обнуляет прежнее значение. Имя источника и его
   стабильная идентичность должны переживать изменение имени карточки.
6. Сеть не переписывать целиком: сохранять management/primary IP, интерфейсные
   назначения, pfSense и существующие связи; provider allocations хранить с
   учётом области аккаунта/проекта/сети. Не считать endpoint адресом WAN.
7. Регион/площадка: реальные provider ID, обновление названий и размещения без
   дублей. Отсутствующий регион не выдумывать. Не удалять общий регион только
   потому, что один аккаунт перестал его использовать.
8. Расписание аккаунта: интервалы 1,2,3,4… дней, календарный месяц и выбор дат/
   времени с часовым поясом. Минимальный период — сутки. Ручной запуск,
   отключение, история, следующий запуск, отсутствие параллельных запусков,
   восстановление после перезапуска и контролируемые повторы ошибок.
9. Отсоединение ресурса и отключение аккаунта отдельно от удаления. Удаление
   аккаунта удаляет созданные им ресурсы NetBox и локальные секреты/расписание.
   Нужны происхождение объектов, предварительный план, бэкап и журнал результата.
   Ранее существовавшие и лишь связанные карточки не считать созданными аккаунтом:
   снять provider-сведения, сохранить их данные и связи других источников.
   Внешние зависимости не удалять каскадом без отражения в плане.
10. Неизвестный результат записи: сверка и идемпотентное восстановление, без
    повторного создания. Размер аккаунта, пагинация, частичный отказ API,
    перезапуск и timeout не должны молча приводить к потере ресурсов.

## Сценарии приёмки (все пока NOT RUN)

| ID | Сценарий | Проверяемый результат |
|---|---|---|
| T01 | Полный импорт аккаунта в тест | Все категории учтены; native VM/Device созданы либо объяснён конфликт |
| T02 | Повтор неизменённого сбора | Нет дублей и лишних записей |
| T03 | ESXi/Proxmox/ручная карточка до Selectel | Принята существующая карточка, PK и IP сохранены |
| T04 | Selectel до добавления гипервизора | Гипервизор принимает provider-карточку |
| T05 | Одинаковая конфигурация разных серверов | Нет ложного объединения |
| T06 | WAN только в снимке pfSense | Показана цепочка адрес → интерфейс → VM → Device |
| T07 | Старый/перемещённый/подменённый снимок | Не используется как актуальное доказательство |
| T08 | Изменение конфигурации/имени у Selectel | Provider-поля обновлены; следующий sync их не отменяет |
| T09 | Регион/площадка меняются или отсутствуют | Верное размещение без фиктивного региона и дублей |
| T10 | Суточное/месячное/датированное расписание | Верный следующий запуск, timezone, restart, без наложения |
| T11 | Отключить и включить аккаунт | Отключённый не запускается; данные сохранены |
| T12 | Отсоединить один ресурс | Остальные связи и данные не изменены |
| T13 | Удалить аккаунт со смешанным происхождением карточек | Созданные удалены; принятые ранее существовавшие сохранены |
| T14 | Зависимости других источников при удалении | Явный план конфликтов, нет скрытого каскада |
| T15 | Большой аккаунт, частичные права, сбой одной категории | Полнота/ошибки видимы, старые данные не обнулены |
| T16 | Timeout/потеря ответа/перезапуск во время импорта | Идемпотентная сверка без дублей |
| T17 | Второй аккаунт с похожими именами/IP | Нет смешения областей и удаления чужих ресурсов |

Для каждого запуска сохранить версию Sync/Guard, время, ID аккаунта, итоговые
счётчики, отчёт до/после и найденные ошибки. Не включать секреты.

## Состояние разработки, не инструкция к production-развёртыванию

Изменения находятся локально. Они не развёрнуты; приёмка на тестовом NetBox ещё не выполнена.

- Расписание/отключение подключены к API и UI Sync. По умолчанию старые аккаунты
  остаются без расписания. Отключение не обрывает уже начавшуюся транзакцию записи.
- В Guard добавлен opt-in `PLUGINS_CONFIG['netbox_guard']['selectel_native_reconcile'] = True`.
  Этот режим включает native reconcile после загрузки реестра, затем заполнение
  новых карточек снимком, в одной транзакции с общей квитанцией.
- Режиму нужны миграции `0013_provider_creation_provenance`, `0014_provider_lifecycle` и разрешения,
  выдаваемые `configure_selectel_mvp --native-resources --lifecycle` (остальные аргументы
  команды сохраняются). Права изменения IP не выдаются.
- Включать режим следует только при тестовом развёртывании после проверки
  интеграционного сценария. По умолчанию поведение импорта остаётся registry-only,
  что теперь явно показывается в результате UI.
- Происхождение фиксируется только при реальном создании, не задним числом для
  старых объектов и не при привязке существующего объекта.
- Добавлены приоритет полей, обратное сопоставление по аппаратным ID,
  размещение по стабильному идентификатору, просмотр и выполнение отсоединения/удаления.
  Неподтверждённая операция удаления повторяется с прежней квитанцией; аккаунт
  остаётся отключённым. После подтверждённого удаления удаляются пароль и расписание.
- Для текущей тестовой приёмки пользователь явно выбрал обновление без бэкапа.
  Приложение не создаёт бэкап БД автоматически. Не выполнять удаление реальных ресурсов до прохождения изолированного
  `tests/netbox_selectel_lifecycle_scenario.py` и проверки предлагаемого списка.

## Матрица приоритета

| Поле | Правило |
|---|---|
| Device/VM name | Непустое свежее имя Selectel; при конфликте короткий стабильный суффикс идентичности |
| Device serial | Только системный серийный номер; не UUID аренды, диска или платы |
| VM vcpus / memory | Число vCPU и MiB RAM из свежего flavor Selectel |
| VM status | Только известное состояние без незавершённой задачи провайдера |
| Site / Region | UUID площадки или availability zone + область аккаунта/региона; название можно обновлять |
| Selectel configuration / OS / networks | Авторитетная проекция доступных данных провайдера; сеть показана как сведения, не переназначение IP |
| Primary/management IP, интерфейсы, pfSense | Не изменяются этим импортом |
| Идентичность гипервизора, его исходное имя, локальные CPU-поля | Дополнительные наблюдения Sync; конфигурация Selectel хранится отдельно, без разбора произвольной строки в CPU/RAM |

Неполный/ошибочный ответ сохраняет последние известные значения и их происхождение.
SQL-защита не позволяет обычному Sync перезаписать приобретённые поля. Sync исключает
их из своего плана обновления VM; неизменяемые provider CF остаются в полном merged map.

## Условия и оставшиеся ограничения

- Обратное сопоставление автоматически возможно при единственном совпадении свежих
  типизированных аппаратных идентификаторов. Неоднозначность требует проверки.
  Стандартный Proxmox API сейчас не даёт сборщику системные DMI: по одной конфигурации
  или IP привязка не подтверждается. В onboarding нужно выбрать площадку существующей
  provider-карточки; неподходящая область кластера блокирует применение.
- Если изменение Site противоречит стойке, хосту VM или области кластера, новое размещение
  сохраняется в provider snapshot как `placement_pending`, UI сообщает о проверке.
  Общий кластер не переносится автоматически.
- Отсоединение ставит запрет повторного автоматического принятия ресурса. Карточка,
  текущие native-значения, IP и чужие sync identities сохраняются.
- Для удаления нужны доказательства создания. Унаследованные IPAM-проекции без
  доказательств происхождения и provider network links пока блокируют операцию.
  Они не удаляются и не маскируются как успешное полное удаление аккаунта.
- Восстановление неизвестного результата обычного импорта (S11) остаётся отдельной
  доработкой; реализованное восстановление квитанции относится к lifecycle-операциям.
