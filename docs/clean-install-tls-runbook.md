# Clean Debian DNS/TLS rehearsal (operator executed)

This runbook is for a wiped disposable VM. It is not authorization to deploy. Do not
use legacy paths, naming migration, old env files or cleanup commands. NetBox remains
external. Read [TLS boundaries](tls.md) and [both ingress modes](external-ingress.md) before executing. Stop at every failed gate;
do not bypass certificate verification or manually fabricate installer config.

## 1. Host and release prerequisites

Use a trusted administrative shell. Supply the full 40-character commit from the
accepted deployment-layout report after it has been explicitly published or securely transferred.
`94451ab` predates TLS; `96a3dce` supports standalone TLS only. External mode
and root-level systemd/corporate TLS support require the later deployment-layout
commit from the completion report. This task does not authorize a push.

```sh
set -eu
ROOT=/netbox-sync-test
TLS_DIR=/etc/netbox-sync-test/cert
: "${INGRESS_MODE:?Choose standalone or external explicitly}"
case "$INGRESS_MODE" in standalone|external) ;; *) exit 1;; esac
: "${RELEASE_COMMIT:?Set the reviewed full TLS release commit}"
case "$RELEASE_COMMIT" in *[!0-9a-f]*|'') exit 1;; esac
test "${#RELEASE_COMMIT}" -eq 40
cat /etc/os-release
python3 --version
git --version
openssl version
curl --version
tar --version
command -v flock install systemctl getent ss
sudo docker version
sudo docker compose version
sudo docker info --format '{{json .SecurityOptions}}'
systemctl is-active docker
ps -p 1 -o comm=
date -u
getent passwd 10001 || true
getent group 10001 || true
sudo ss -ltnp '( sport = :80 or sport = :443 or sport = :8000 or sport = :5432 )'
```

Expected: Debian, Python >=3.10, rootful Docker/Compose v2-compatible plugin,
systemd PID1, OpenSSL with `x509 -checkhost`, GNU tar, util-linux, Git/curl/CA trust.
Host time must be correct. No unrelated host account should use numeric ID 10001.
Standalone requires free 80/443. External mode reserves those ports for the separately
managed shared ingress, which may already be running. No Sync backend/database port
should be published. External mode requires Compose >=2.24.4.
Stop for unavailable tools, daemon, unsupported rootless/userns configuration, port
conflicts or incorrect time. Image builds require DNS/HTTPS access to registries,
Python and npm package sources. Repository code does not prescribe RAM/disk minimums;
verify sufficient free capacity with `df -h /opt /var/lib/docker` before building.

## 2. DNS and separate NetBox endpoint


Expected: Sync resolves to this VM from operator machines; NetBox resolves to its

or missing DNS. Zero-source startup can precede NetBox readiness, but completing
onboarding cannot. For co-hosting select `INGRESS_MODE=external`: both DNS names
may point to the same VM, whose separately configured shared ingress owns 80/443.
Standalone owns those ports itself and cannot share them with a second proxy. No NetBox certificate directories are created
by this runbook; its external installation owns those paths and its TLS process.

## 4. Create canonical certificate directories and copy operator material

The following is the supported directory-creation command. It is idempotent for an
already correct layout and rejects conflicting existing ownership/modes:

```sh
sudo python3 deploy/install.py --root "$ROOT" --tls-dir "$TLS_DIR" --init-tls-layout --ingress-mode "$INGRESS_MODE"
sudo stat -c '%u:%g %a %n' ${ROOT} ${ROOT}/secrets \
  ${ROOT}/secrets/tls ${ROOT}/secrets/ca
```

Expected root:root 0755 deployment root, root:root 0700 secrets, root:10001 0750 tls,
root:root 0755 ca. No certificates, env files or containers are generated by this step. Standalone also
creates `$TLS_DIR` as root:10001 0750; external does not create or require it.

Standalone only: set `SYNC_FULLCHAIN_SOURCE` and `SYNC_PRIVATE_KEY_SOURCE` to the operator's actual
protected staging paths. Never use command substitution to read a key or enable
shell tracing. Install leaf-first full chain and matching unencrypted private key:

```sh
if [ "$INGRESS_MODE" = standalone ]; then
: "${SYNC_FULLCHAIN_SOURCE:?Set operator full-chain file path}"
: "${SYNC_PRIVATE_KEY_SOURCE:?Set operator private-key file path}"
: "${DH_PARAM_SOURCE:?Set operator PEM DH-parameters file path}"
sudo install -o 0 -g 10001 -m 0640 -- "$SYNC_FULLCHAIN_SOURCE" ${TLS_DIR}/ssl.crt
sudo install -o 0 -g 10001 -m 0640 -- "$SYNC_PRIVATE_KEY_SOURCE" "${TLS_DIR}/ssl.key"
sudo install -o 0 -g 10001 -m 0640 -- "$DH_PARAM_SOURCE" "${TLS_DIR}/dhparam.pem"
fi
```

Optional, only when external NetBox uses an issuer absent from Requests' standard CA
bundle, set `NETBOX_CA_SOURCE` to an approved public PEM CA bundle (no private key):

```sh
if [ -n "${NETBOX_CA_SOURCE:-}" ]; then
  sudo install -o 0 -g 0 -m 0644 -- "$NETBOX_CA_SOURCE" ${ROOT}/secrets/ca/netbox-ca.pem
fi
sudo python3 deploy/install.py --root "$ROOT" --tls-dir "$TLS_DIR" --check-tls --ingress-mode "$INGRESS_MODE" --public-url https://netbox-sync-test.indeed-id.hq
if [ "$INGRESS_MODE" = standalone ]; then
sudo stat -c '%u:%g %a %n' ${TLS_DIR}/ssl.crt ${TLS_DIR}/ssl.key ${TLS_DIR}/dhparam.pem
fi
```

Standalone expects TLS check success and all three files 0:10001 640. External mode
checks URL/optional NetBox CA only and needs no local public certificate/key; outer
ingress owns those files and must be verified separately. Stop on absent, expired,
hostname-mismatched, invalid or incorrectly protected material. Never generate fake
production certificates or use an insecure option to pass this gate.

## 6. Containers, isolation, DB and timer

## 7. External mode upstream, then public HTTPS, chain and SPA

For external mode, authorize the separately managed host ingress worker's group
access as described in [the socket contract](external-ingress.md). Configure only
outside this repository: public TLS/HTTP redirect and hostname routing to the exact
Unix upstream. NetBox routing remains separately owned. Verify local Sync first:

```sh
if [ "$INGRESS_MODE" = external ]; then
  sudo stat -c '%u:%g %a %n' ${ROOT}/ingress
  sudo test -S ${ROOT}/ingress/upstream.sock
  sudo curl --unix-socket ${ROOT}/ingress/upstream.sock --noproxy '*' \
    --fail --silent --show-error --max-time 10 \
    -H 'Host: netbox-sync-test.indeed-id.hq' -H 'X-Forwarded-Proto: https' \
    http://localhost/api/v1/health
  test "$(sudo docker inspect --format '{{.HostConfig.NetworkMode}}' "$(sync_compose ps -q netbox-sync-proxy)")" = none
fi
```

Expected protected directory/socket, health success and networkless Sync nginx.
Stop for missing access or wrong socket ownership; never relax it to world-accessible.
After outer ingress configuration, perform all public checks below in either mode.

Run from an operator machine with actual DNS access. Set `SYNC_CA_VERIFY` to a public
PEM trust bundle accepted by your organization for the Sync certificate issuer.
For public issuers on Debian this can be `/etc/ssl/certs/ca-certificates.crt`. It is
not the server private key and need not be the NetBox CA bundle.

```sh
: "${SYNC_CA_VERIFY:?Set approved public CA trust bundle path}"
curl --noproxy '*' --silent --show-error --max-time 15 --dump-header - --output /dev/null \
  http://netbox-sync-test.indeed-id.hq/setup
openssl s_client -connect netbox-sync-test.indeed-id.hq:443 \
  -servername netbox-sync-test.indeed-id.hq -verify_hostname netbox-sync-test.indeed-id.hq \
  -verify_return_error -CAfile "$SYNC_CA_VERIFY" </dev/null
curl --noproxy '*' --fail --silent --show-error --max-time 15 --cacert "$SYNC_CA_VERIFY" \
  https://netbox-sync-test.indeed-id.hq/api/v1/health
for route in / /setup /sources /sources/test-source /sources/add /runs /runs/test-run-id /diagnostics; do
  test "$(curl --noproxy '*' --silent --show-error --max-time 15 --cacert "$SYNC_CA_VERIFY" \
    --output /dev/null --write-out '%{http_code}' "https://netbox-sync-test.indeed-id.hq$route")" = 200
done
for route in /api/nonexistent /assets/missing.js /unknown-frontend-route; do
  test "$(curl --noproxy '*' --silent --show-error --max-time 15 --cacert "$SYNC_CA_VERIFY" \
    --output /dev/null --write-out '%{http_code}' "https://netbox-sync-test.indeed-id.hq$route")" = 404
done
curl --noproxy '*' --fail --silent --show-error --max-time 15 --cacert "$SYNC_CA_VERIFY" \
  https://netbox-sync-test.indeed-id.hq/api/v1/bootstrap
```

Expected 308 with exact Location `https://netbox-sync-test.indeed-id.hq/setup`, valid
chain/hostname, health success, SPA routes 200, missing API/assets/unknown routes 404,
Bootstrap FRESH with no tokens. In browser developer tools verify referenced built JS
and CSS return 200. Stop on any TLS, routing, asset or status mismatch; never use -k.

## 8. External NetBox and first-run completion

Have the external NetBox operator install its HTTPS endpoint and prerequisites from
[tls.md](tls.md#external-netbox-prerequisites). Its own proxy terminates its TLS and
owns its certificate/key layout. Configure its allowed hosts/origin for
`netbox-test.indeed-id.hq`. Sync has no Django CSRF settings; it enforces its own exact
public origin. There is no cross-origin browser request to NetBox.

Verify external NetBox TLS from a machine with a public issuer trust bundle:

```sh
: "${NETBOX_CA_VERIFY:?Set approved NetBox issuer trust bundle path}"
openssl s_client -connect netbox-test.indeed-id.hq:443 \
  -servername netbox-test.indeed-id.hq -verify_hostname netbox-test.indeed-id.hq \
  -verify_return_error -CAfile "$NETBOX_CA_VERIFY" </dev/null
```

Expected valid chain/hostname. API authentication is tested through onboarding,
not tokens on the shell command line. For container-level CA configuration check
without reading key/token files:

```sh
sync_compose exec -T netbox-sync-bootstrap-worker python -c \
  "import requests; from netbox_sync.netbox_tls import configure_session; s=configure_session(requests.Session()); print('additional CA' if isinstance(s.verify,str) else 'standard CA'); assert s.trust_env is False; s.close()"
```

Expected additional CA only if the approved bundle was installed; invalid material
must fail. This checks configuration, not live chain trust. The definitive container
connection gate is the Web **Test connection and prerequisites** operation below.

Open `https://netbox-sync-test.indeed-id.hq`. Expect Welcome with no sources. Enter
`https://netbox-test.indeed-id.hq` and distinct read/apply tokens, save, then test.
Expected VALIDATED with all custom-field checks satisfied; Finish yields READY.
Failure must remain gated with a safe error, never skip validation. No NetBox objects,
VLANs/Prefixes, sources, provider tokens or infrastructure are created automatically.
Do not begin source/provider rehearsal until this first-run gate passes. Real
Debian/systemd/reboot and real NetBox acceptance must be recorded separately from
repository automation; this runbook has not been executed on the VM by the agent.

For a partial activation failure at proxy creation, see the [tmpfs recovery gates](proxy-tmpfs-recovery.md) before any retry.
