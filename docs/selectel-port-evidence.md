# Дополнительные сведения о физических портах Selectel

Этап: исследование API на тестовом стенде, 2026-10-13. Это отдельный сбор
свидетельств для общего алгоритма, ещё не автоматическое создание кабелей.

## Что проверяем

Официальная [спецификация Dedicated API](https://docs.selectel.ru/api/dedicated/)
описывает методы ниже. Используется базовый URL
`https://api.selectel.ru/servers/v2`, как в
[официальном SDK](https://github.com/selectel/dedicated-go).

| GET относительно базового URL | Назначение |
|---|---|
| `/resource` и `/resource/{uuid}` | Ресурс, область размещения и hardware UUID |
| `/resource/{uuid}/aux_network_info` | Дополнительные сведения о портах ресурса |
| `/network/port/hw/{hw_uuid}` | Порты конкретного оборудования |
| `/network/port/{uuid}` | Идентичность и состояние порта, признаки агрегации |
| `/network/port/{uuid}/network` | Сети, подключённые к порту |

В схеме `aux_network_info` есть `mac_address`, `peer_name`, `peer_ip`, ASN,
`client_ip`, `subnet`, `availability_zone`, `leaf_pairs`, `loopback_ips` и
`network_interfaces_ip`. Их наличие в схеме не гарантирует заполнение для
конкретного типа сервера. Роль MAC (NIC сервера или оборудование сети) пока
не подтверждена. Эти значения нельзя сразу применять как доказательство кабеля.

## Сбор без изменения конфигурации

`python -m selectel_audit.port_probe --account ACCOUNT --output DIR` запрашивает
IAM-токен скрытым вводом, проверяет область аккаунта и автоматически обходит
видимые выделенные ресурсы. Идентификаторы серверов, NIC и NetBox не зашиты.
Токен не передаётся через аргументы командной строки и не сохраняется в отчётах.
Остаются только разрешённые технические поля; свободный текст и секреты исключены.

`deploy/probe-selectel-ports-test.sh ACCOUNT` запускает сбор в изолированном
контейнере на `netbox-test`. Образ должен быть предварительно собран из той же
ревизии. Скрипт не импортирует результаты, не обновляет Guard/Sync и не обращается
к NetBox. Существующие IP управления и назначения гостям сохраняются.

Файлы: `summary.json` — краткий итог и найденные дополнительные сведения;
`ports.json` — выбранные технические поля по каждому endpoint с временем запроса.
Это не полный дамп ответов API. Для каждого запроса сохраняется отдельный статус:
получено, пусто, 403, 404, 202, ошибка или неполная пагинация. HTTP 404 не трактуется
как доказательство отсутствия услуги, HTTP 200 — как полнота аккаунта. 202 не
вызывает запуск фоновых действий или бесконечный опрос. Ограничения числа запросов,
ресурсов и портов отмечаются явно. Сбор сохраняет частичный отчёт при отказах.

## Условия будущего автоматического сопоставления

- Сохранить отдельно постоянный provider UUID, связь с hardware UUID, сетевую
  область и наблюдения гипервизора. Имя порта без идентичности коммутатора
  не уникально; одинаковый `GE1/0/4` не означает один порт.
- Подтверждать pNIC по проверенной семантике данных: например, документированному
  MAC серверного интерфейса и уникальному совпадению в актуальном снимке хоста,
  либо согласованным идентификаторам chassis/port в API и LLDP/CDP. При противоречии
  или неоднозначности оставлять связь неподтверждённой с объяснением причины.
- `is_enabled` — состояние из API, а не доказательство доступности, трафика или
  намерения владельца. Не включать отключённые порты и не удалять существующие
  связи из-за отключения. Агрегированные порты не сводить к одному NIC.
- Путь VM → bridge/vSwitch → pNIC полезен независимо от подтверждения порта
  провайдера. Различать конфигурационный путь, наблюдение соседства и кабель.
- Схемы draw.io и ручные таблицы — дополнительный источник с происхождением
  и датой; не источник автоматической записи. Цвета и отсутствие линии не
  доказывают отключение порта. Расхождения показывать пользователю.
- Не устанавливать LLDP-службы, не менять ACL и сетевые настройки автоматически.
  При подключении объяснять недостающую возможность и её минимальные требования.

После получения реальных ответов уточняется контракт полей и добавляется
автоматический сбор в обычный цикл. Сам probe не доказывает готовность такого
сопоставления. Общие требования: [автоматизация сети](provider-network-automation.md).
