# Selectel MVP: подключение через NetBox Sync

## Границы версии

Окружение приёмки — только тестовое. Путь: «Источники → Selectel».
Доступ к аккаунтам пока только у администратора Sync (bootstrap.manage): данные
аккаунта не наследуют команды или права отдельного ESXi/Proxmox-источника.

1. Установить `deploy/update-selectel-mvp-test.sh` на netbox-test. Скрипт проверяет
   тестовые каталоги и URL, сохраняет контрольные сетевые данные, обновляет Guard
   и Sync. Отдельный пользователь netbox-sync-selectel получает права импорта
   реестров и view/change Device/VM, без add/delete и без прав администратора.
   Обычные токены гипервизоров не получают новых прав.
2. В разделе Selectel указать название, номер аккаунта, имя и пароль сервисного
   пользователя с правами чтения нужных продуктов/проектов. Сохранение не запускает
   сбор. Повторное сохранение того же номера заменяет реквизиты подключения.
3. «Собрать и обновить» запускает фоновое чтение API и импорт. Можно закрыть страницу.
   Провайдерские операции — чтение, кроме выпуска IAM-токенов авторизации.
4. Открыть результат по категориям, затем «Ресурсы в NetBox». Проекты и имена
   сохраняются из API, существующие серверные привязки отображаются в реестре.

Рабочие категории: выделенные серверы, облачные VM, DNS-зоны/записи,
Swift-контейнеры объектного хранилища и их доступные настройки/домены. Серверные
снимки включают доступные ресурсы, размещение и сетевые сведения. Другие коллекции
API участвуют в отчёте покрытия, но не обещают отдельные native-модели NetBox.
Swift-контейнер не объявляется S3-бакетом только по имени.

## Что делает импорт

Одна транзакция обновляет серверный реестр и DNS/хранилище. Сведения Selectel у
уже связанных Device/VM обновляются через Guard. Повтор одного nonce с тем же
снимком возвращает квитанцию, другой снимок с тем же nonce отвергается.
При ошибке одной части весь импорт откатывается. Пропавшие ресурсы не удаляются,
последние успешные разделы сохраняются при неполном сборе.

MVP не создаёт новые Device/VM, не принимает сомнительные сопоставления и не
перестраивает native IPAM автоматически. Доступный операторский reconcile остаётся
отдельным процессом с просмотром плана. Основной реестр пригоден к использованию
даже без аппаратных идентификаторов. IP управления, назначения интерфейсов, NAT
и размещение pfSense импортом не изменяются. Ревизии provider bindings могут
законно увеличиться при обновлении сведений провайдера.

## Доступ и эксплуатация

Пароли Selectel и отдельный токен NetBox хранятся в root-only каталоге selectel
в существующем каталоге секретов NetBox (0700/0600), не в журнале, argv или UI.
Это защищённые файлами секреты, не шифрование диска. Резервные копии этого каталога
содержат секреты и требуют такой же защиты, как существующие секреты Sync.
Сеть и разбор провайдерских ответов выполняет непривилегированный дочерний процесс.
Запуски Selectel сериализуются. На время импорта берётся общий apply lock.
Сбор ограничен 2800 секундами и размером ответа; при прерывании UI не сообщает успех.
Повторный запуск после ошибки читает новый снимок; автоматического удаления нет.

Готовность в репозитории подтверждается тестами. Завершение MVP на конкретной
установке требует успешного сбора новым сервисным пользователем, проверки
категорий, переходов в NetBox и сетевых контрольных данных.

## Приёмка на тестовом

- Подключить аккаунт с корректными и некорректными реквизитами; секрет не возвращается.
- Выполнить сбор; проверить реальные названия проектов, серверов, DNS и контейнеров.
- Проверить, что частичное покрытие не показано как полный сбор аккаунта.
- Проверить сохранность management IP, pfSense, NAT и provider identities;
  при сравнении учитывать ожидаемый рост ревизии сведений Selectel.
- Повторить сбор и убедиться, что не появились дубликаты native Device/VM.
- Перезапустить Sync и проверить сохранность подключения и результата.
