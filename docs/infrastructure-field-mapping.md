# Поля инфраструктуры: проект контракта

Основание: [согласованная модель](infrastructure-target-model.md).
Статус: контракт реализации. Проверки и границы приёмки — в
[чек-листе](selectel-completion-checklist.md); это не отчёт о миграции живой базы.

| Данные | Назначение | Источник/условие | При удалении аккаунта |
| --- | --- | --- | --- |
| UUID ресурса | ProviderBinding + идентичность провайдера | Selectel; область аккаунта/проекта/региона | Удалить связь, оставить защитную квитанцию |
| UUID гипервизора/гостя | sync_identities | ESXi/Proxmox | Сохранить чужую идентичность |
| Имя ресурса | Device.name / VirtualMachine.name | Selectel после подтверждения связи | Прежнюю карточку сохранить; не выдумывать историческое имя |
| Состояние облачной VM | VirtualMachine.status | Явное преобразование состояний Selectel | По происхождению карточки |
| Состояние физического сервера | Device.status | Состояние услуги не равно питанию; отдельная таблица соответствий | По происхождению карточки |
| Серийный номер | Device.serial | Только достоверный идентификатор корпуса, не UUID услуги или диска | Не стирать чужое значение |
| Модель | Device.device_type | Проверенные производитель/модель; неизвестное явно обозначить | Общие типы не удалять при чужих зависимостях |
| Процессоры, RAM, диски физического сервера | Структурированная спецификация провайдера | Компоненты, количество, единицы; без фиктивных полей VM | Удалить сведения Selectel |
| vCPU, память VM | VirtualMachine.vcpus / memory | Selectel для облачных, гипервизор для гостевых | По происхождению карточки |
| Диски VM | Стандартная модель диска VM, если поддержана установленной версией | Устойчивый ID тома/диска; корректные единицы | Только доказанно созданные аккаунтом |
| Регион/площадка | Region / Site | Selectel, с проверкой существующих зависимостей | Сохранить общие/ранее существовавшие |
| Кластер | Cluster | Реальная структура ESXi/Proxmox; не по факту наличия сервера | Не удалять чужие кластеры |
| Физический хост VM | VirtualMachine.device | Подтверждённое размещение гипервизора | Не терять связи существующих гостей |
| Назначенный интерфейсу IP | IPAddress + assigned_object | Подтверждённый владелец/область сети | Сохранить чужие назначения |
| Основной IP | Device/VM.primary_ip4/6 | Адрес собственного интерфейса, не WAN гостя | Не переносить и не стирать чужой IP |
| Выделенный провайдером IP | Сведения выделения + сетевой объект при подтверждённой области | Selectel, без предположения владельца интерфейса | По журналу происхождения |
| Prefix/VLAN/VRF | Штатные IPAM-объекты | Точное соответствие проекта/сети, не имя | Только собственные; зависимости проверяются |
| pfSense WAN/LAN/NAT/firewall | Наблюдения pfSense со ссылками на подтверждённые объекты | Снимок + время + известная VM/Device | Сохранить сведения независимого источника |
| Бакет | Карточка storage_container | Аккаунт/проект/регион/имя в установленной области | Удалить реестр аккаунта |
| DNS-зона/набор записей | Карточки dns_zone / dns_rrset | ID зоны, тип, имя, TTL, содержимое | Удалить реестр аккаунта |
| Глобальный роутер | Новая карточка реестра и вкладка | Проверенная схема API, область и состояние | Удалить собственный реестр |
| Подключения/маршруты роутера | Типизированные дочерние данные/связи | Только полученные API сведения; полнота отдельно | Не затрагивать независимые сети |

## Правила изменения

Уточнения оператора от 4 ноября 2026: Site сохраняет смысл площадки
(SPB-4, ru-9a); аккаунт и проект показываются отдельно и не подменяют площадку.
Если Primary IPv4 пуст, предпочитается публичный адрес, затем внутренний.
Все известные адреса остаются видимыми. Это правило выбирает основной адрес
только среди подтверждённо принадлежащих интерфейсам этой карточки: выделение
адреса серверу в панели провайдера само по себе не доказывает владельца NIC.
Существующий Primary и назначения другим карточкам сохраняются.

Отсутствие значения, недоступная категория и подтверждённый пустой результат —
разные состояния. Не заменяем неизвестное нулём. Не перезаписываем стандартное
поле значением с другим смыслом. Перенос размещения или IP требует проверки
связанных объектов. Связь с существующей карточкой не делает её собственностью
Selectel и не разрешает удалять её при удалении аккаунта.

## Открытые проверки реализации

Штатная модель [VirtualDisk](https://netboxlabs.com/docs/netbox/v4.4/models/virtualization/virtualdisk/)
предусматривает отдельные диски VM и размер в мегабайтах. Проекция Selectel
использует ID тома и единственное прикрепление к VM, переводит GiB в десятичные MB
и сохраняет происхождение для повтора и удаления. Multiattach не угадывается.
[Cluster](https://netboxlabs.com/docs/netbox/v4.4/models/virtualization/cluster/)
описывает ресурсы виртуализации, поэтому создание кластеров для бакетов/DNS
не используется как замена их собственным карточкам.

- Выяснить текущие причины отказа у названных облачных VM через интерфейс причин.
- Проверить совместимость дисков VM с установленной версией и текущим импортом.
- Проверить спецификацию глобального роутера: вложенные данные, пагинацию,
  отдельные запросы деталей, доступы и частичные ответы.
- Проверить наличие подходящих штатных моделей для DNS/бакетов/маршрутизации
  до выбора окончательной схемы расширения.

## Реализованная native-проекция 4 ноября

Облачный порт связывается по device_id VM и network/subnet ID в области аккаунта,
проекта и региона. Создаваемые сетевые объекты имеют отдельные VRF, чтобы
одинаковые внутренние адреса независимых сетей не объединялись. Floating IP
ссылается на подтверждённый fixed IP штатным nat_inside; Primary предпочитает
публичный адрес, затем внутренний, сохраняя уже заполненное поле. Свой IP
не переносится на чужой интерфейс. Снимок без свежего ресурса не проецируется.

Поле Site хранит реальную площадку. При отсутствии AZ известный регион позволяет
создать VM в явно региональной площадке «зона не указана». Аккаунт/проект
показываются отдельно. UUID остаётся идентификатором провайдера, не serial.
Для VM не создаётся неизвестный физический хост или выдуманный кластер.
