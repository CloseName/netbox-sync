# Selectel в NetBox

Меню **NetBox Sync → Ресурсы провайдеров** открывает ресурсы единственного
аккаунта сразу. При нескольких аккаунтах сначала показывается таблица аккаунтов.
Право `netbox_guard.view_resourceregistry` открывает реестры всех аккаунтов;
ссылки на Device/VM дополнительно учитывают права просмотра этих объектов.

Вкладки: выделенные серверы, облачные серверы, бакеты S3/Swift, DNS-зоны.
В списках есть фильтр проекта и поиск. DNS-записи находятся внутри зоны;
у бакетов показаны доступ, объём, количество объектов, лимиты и домены.
Диагностика, история импорта и JSON не выводятся. Они сохраняются в базе.

Название сервера берётся из Selectel. Колонка «Объект NetBox» показывает
подтверждённую ProviderBinding. Имя связанного сервера открывает Device/VM;
«Сведения» открывают поля провайдера. Отсутствие связи явно отображается.
Имена проектов сохраняются из исходного аудита. `provider_project_names`
однократно исправляет старые ID-заглушки из **того же** inventory.json,
с журналированием изменения; существующие нормальные имена не заменяются.

## Автоматическое сопоставление и создание

`provider_reconcile --account ACCOUNT --actor USER` строит план по сохранённому
серверному реестру. Применение требует `--apply --fingerprint HASH --nonce UUID`.
Тестовый runner `deploy/reconcile-selectel-test.sh ACCOUNT --apply` выполняет
планирование, применение и проверку сохранности сетевых связей. Его можно
включать после успешного серверного импорта; расписание этим релизом не меняется.

- Существующая привязка сохраняется, исчезнувшая цель не пересоздаётся молча.
- Однозначный достоверный serial или ранее записанный точный provider identity
  позволяют привязать существующий объект через Guard.
- Совпадение имени или IP — кандидат, который блокирует создание дубликата,
  но само по себе не доказывает идентичность. Два ресурса с одним serial
  не могут автоматически получить одну цель.
- Выделенный сервер без serial не создаётся автоматически: исключить уже
  зарегистрированный под другим именем гипервизор по этим данным нельзя.
- Для облачных серверов без кандидатов создаётся VM; для выделенных с serial —
  Device. Создаются провайдерские Site и, при наличии явного региона, Region.
  ЦОД/зона не выдаётся за географический регион. Неизвестная модель оборудования
  остаётся явно неопределённой. Название Selectel в реестре не изменяется.
- Повторный запуск использует постоянную привязку. Нужен полный просмотр
  Device/VM/IPAM, право Guard и права на создаваемые/изменяемые объекты.
- Для новой привязки или создания нужен успешный снимок не старше 48 часов;
  пропущенные в последнем импорте серверы не создаются. Текущее состояние
  облачной VM должно быть ACTIVE/SHUTOFF/SHELVED/SHELVED_OFFLOADED.

Применение атомарно, сериализовано с импортом аккаунта, защищено от устаревшего
плана и повторов nonce. Старые Device/VM не переименовываются, размещение,
primary IP, интерфейсы и NAT не меняются. Новым VM переносятся vCPU и память;
выделенным — serial. Обновление оборудования уже привязанных объектов,
перенос интерфейсов/IP облачных VM и самостоятельное включение расписания
не входят в этот шаг. Бакет не моделируется как Device или виртуальный диск.

Сведения провайдера не доказывают доступность ОС, роль гипервизора или физический
кабель. Неподтверждённые NIC ↔ порт Selectel остаются неподтверждёнными.
