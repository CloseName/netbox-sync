# Автоматическое сопоставление инфраструктуры провайдера

Статус: требования и результаты тестовой проверки, 2026-10-13.
Это целевая архитектура, а не заявление о готовности перечисленных возможностей.
До отдельного согласования развёртывание только на тестовом стенде.

## Реализованный этап: диагностика сетевых снимков

- Proxmox: сверяются мосты гостей, явные родители VLAN, порты bridge и участники
  bond с интерфейсами ответа API. Пропущенные ссылки видны в review Sync и панели
  NetBox. `references_resolved` означает только разрешение известных ссылок,
  а не полноту всей сети. Пустой изолированный bridge допустим.
- Отсутствующий мост не объявляется автоматически ошибкой прав. Пользователь
  проверяет конфигурацию и доступ пользователя **и** токена к конкретному мосту.
  Для чтения bridge в современных Proxmox требуется проверка SDN.Audit;
  дополнительные ACL не должны сужать существующие эффективные права.
- ESXi: один `HostNetworkSystem.QueryNetworkHint` на хост через существующее
  API-подключение. Сохраняются интерфейс, протокол, ID соседа/порта, имя и платформа
  CDP. Свободные параметры LLDP, сообщения ошибок, TTL и счётчики не сохраняются.
  Объявления с истёкшим TTL исключаются. Статусы: collected, empty, denied,
  unsupported, unavailable, error. Ошибка этого дополнительного чтения не
  прерывает основной сбор. Неудачный новый сбор явно заменяет прежние наблюдения
  статусом ошибки; история снимков остаётся в журнале изменений NetBox.
- Отображение соседей не создаёт кабели, назначения IP или подтверждения портов
  Selectel. Наличие LLDP на Proxmox пока этим этапом не проверяется и не собирается.
- Проверка происходит при сборе и построении плана, до применения. После обновления
  требуется новый план и его обычное применение, чтобы панель получила снимок.

API: [VMware QueryNetworkHint](https://developer.broadcom.com/xapis/vsphere-web-services-api/latest/vim.host.NetworkSystem.html#queryNetworkHint),
[LLDP](https://developer.broadcom.com/xapis/vsphere-web-services-api/latest/vim.host.PhysicalNic.LldpInfo.html).

## Цель и границы

Пользователь подключает аккаунт Selectel и источники гипервизоров, проходит
проверку доступа и видит найденные ресурсы, привязки и недостающие сведения.
Сбор, повторное сопоставление и обновление выполняются по расписанию.
Имена устройств, IP, ID NetBox, имена NIC и мостов не должны быть зашиты в алгоритм.
Два текущих сервера — примеры приёмки, не отдельные правила сопоставления.

## Независимые уровни связей

1. Ресурс Selectel ↔ Device/VM: постоянная привязка по provider/account/kind/native_id.
2. Выделение IP/сегмента серверу провайдером: не означает назначения IP интерфейсу.
3. Назначение IP гостю/хосту и размещение VM: сохраняется из подтверждённых источников.
4. Конфигурационный путь VM → bridge/vSwitch → pNIC: не доказательство маршрутизации.
5. Наблюдение соседа pNIC → объявленный chassis/port: отдельное свидетельство.
6. Подтверждённое соответствие порту провайдера: требует связи с идентичностью
   провайдерского порта, а не только совпадения отображаемого номера порта.

Имя CDP-соседа само по себе не устанавливает владельца или прямой кабель:
объявления могут быть устаревшими, ошибочными или проходить через промежуточную сеть.
Совпадение IP, имени, VLAN или модели оборудования создаёт кандидата, но не
достаточно для автоматического объединения объектов. Неоднозначный кандидат
не должен приводить ни к объединению, ни к созданию дубликата без рассмотрения.

## Проверки подключения и диагностика

- До первой записи проверить доступность API, области аккаунта/проекта/источника,
  права чтения и полноту данных, необходимых каждой возможности.
- Для Proxmox проверять эффективные права пользователя и токена на мосты.
  Успешный GET сети не означает, что все мосты видимы. Сверять ссылки гостей
  и VLAN parents с полученными интерфейсами. Отсутствие объекта без доказательств
  обозначать как неполные данные; не выдавать его автоматически за отсутствие прав.
- Отдельно показывать: получено, пустой ответ, доступ запрещён, возможность
  не поддерживается, сбор не настроен, транспортная ошибка, устаревшее наблюдение.
- Для недостающих прав показывать конкретный субъект, scope и минимальное
  разрешение, а также готовые инструкции. Не расширять ACL и не устанавливать
  службы на гипервизоры автоматически в обычном цикле синхронизации.
- Сбор CDP/LLDP ESXi предусмотреть через API; SSH-команды текущего исследования
  не становятся обязательным пользовательским шагом.
- Для Proxmox предусмотреть явно настраиваемый источник соседства, если его
  нет в используемом API: дополнительный сборщик или данные провайдера/коммутатора.
  Стандартное подключение API не должно незаметно требовать root/SSH.

## Правила сопоставления и хранения

- Нормализовать MAC и портовые идентификаторы без потери исходного значения.
  MAC физического адаптера не путать с MAC bridge, VMkernel или гостя.
- Держать аккаунт, проект, площадку и сетевую область в ключах; одинаковый VLAN
  или номер порта в разных областях не является общей идентичностью.
- Свидетельство содержит источник, время наблюдения, локальный адаптер,
  удалённые идентификаторы и причину вывода. Срок годности и конфликт источников
  учитываются отдельно от постоянной привязки ресурса.
- CDP-сосед, являющийся другим гипервизором, не превращается в порт Selectel.
- При нескольких кандидатах не выбирать первый. Старое подтверждение не
  перепривязывать автоматически при противоречии или пропавшем источнике.
- Ошибка/неполный сбор не очищает прежние подтверждённые значения. Их свежесть
  отображается явно, без выдачи старых данных за текущие.
- Владение задаётся по полям и отношениям: Selectel отвечает за свои выделения
  и идентификаторы, гипервизор — за наблюдаемую конфигурацию. Приоритет провайдера
  не разрешает менять IP управления, назначение гостю или придумывать NAT.
- Записи проходят review/Guard и журналирование; повторный план стабилен.

## Пользовательский сценарий

Подключить аккаунт → проверить доступ → выбрать область → получить инвентарь →
показать существующие привязки и кандидатов → показать план → применить → расписание.
Для каждого отсутствующего ребра интерфейс объясняет, какие данные нужны и где
их получить. Частичная топология остаётся полезной и не блокирует независимые
подтверждённые изменения. Полнота топологии и успех синхронизации — разные статусы.
В NetBox и Map использовать одни и те же отношения и уровни подтверждения.

## Тестовые свидетельства

- После добавления SDN.Audit на три моста пользователю и токену Proxmox
  обычная синхронизация сохранила путь pfSense → vmbr0 → eno1.
- Proxmox: eno1 постоянный MAC 3c:ec:ef:7d:7e:18, член vmbr0;
  eno2 постоянный MAC 3c:ec:ef:7d:7e:19, член vmbr1. LLDP client не установлен:
  отсутствие наблюдений не является отрицательным доказательством соседства.
- ESXi: vmnic0 MAC ac:1f:6b:02:1c:b0, CDP/LLDP не сообщены.
  vmnic1 MAC ac:1f:6b:02:1c:b1, CDP сообщает devId/systemName ESXi-REM.DEV,
  portId vmnic1, hardwarePlatform VMware ESX. Это наблюдение гипервизора,
  а не доказательство соответствия порту Selectel.
- В собранных данных Selectel нет заполненного aux_network_info для этих портов.
  На Proxmox два порта имеют одинаковое имя GE1/0/4, но разные UUID и типы.
  Автоматически подтверждать физические связи с ними пока нельзя.
- Исходное отсутствие снимка и неполная видимость мостов — разные состояния.
  Сохранение снимка затем подтверждено; причина первоначального пропуска записи
  отдельно не установлена. Нехватка SDN.Audit объясняет отсутствие мостов.

## Приёмка общего решения

- Те же сценарии работают при иных именах хостов, bridge/NIC, IP и native IDs.
- Проверяются оба порядка подключения: сначала гипервизор и сначала Selectel.
- Отдельные тесты: скрытые мосты, token privilege separation, пустой CDP/LLDP,
  сосед-гипервизор, совпадающие port names/VLAN в разных областях, bond,
  устаревшие и противоречивые данные, недоступный API, повторная синхронизация.
- IP управления, назначения pfSense, история и provider bindings сохраняются.
- Нет ложных кабелей, дублирования ресурсов или циклических перезаписей.
- Первоначальная настройка внешних прав/источника соседства объясняется в UI;
  после неё обычные циклы не требуют выполнения команд оператором.
