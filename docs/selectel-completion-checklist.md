после обновления остаётся за оператором. Production и расписания не затрагиваются.

## Границы данных

Отсутствие подтверждения владельца интерфейса не заменяется догадкой. Для
выделенного сервера адрес Selectel может принадлежать гостевой pfSense: такой
адрес виден в панели, но не становится Primary гипервизора. У ранее заведённой
VM существующие интерфейсы не переименовываются и не присваиваются провайдеру
по одному имени. Совпавший частный IP без области сети не служит автопривязкой.

VRF новых облачных сетей изолированы по ID сети и области провайдера; это не
утверждение, что между ними отсутствует маршрутизация. Полученная топология
роутеров хранится отдельно. Изменённый вручную собственный компонент не
перезаписывается; при удалении аккаунта конфликт показывается до удаления.
Исчезновение компонента при неполном сборе не удаляет старую запись.

## Приёмка после обновления

1. Собрать оба аккаунта. Проверить `identityclub.ru`, `identityconf.ru`, `mgate`
   и Siena: карточка либо конкретная причина отказа, без выдуманной зоны.
2. На WAF/time-prod проверить интерфейсы, IP, Primary и диски. Повторить сбор:
   ID карточек/компонентов и существующий Primary должны сохраниться.
3. Проверить QA PAM/Build Agent: однозначные кандидаты связываются; неоднозначные
   остаются для ручного выбора с объяснением. WAN pfSense не переносится на ESXi.
4. Открыть оба глобальных роутера, найти адрес внутри подсети, проверить VLAN,
   CIDR, шлюз и служебные адреса; скрытые UUID остаются доступны модели/API.
5. Удалить и подключить аккаунт дважды. Сверить отсутствие дублей и сохранность
   прежних ESXi/Proxmox, чужих интерфейсов/IP и данных другого аккаунта.

Данные будущего конструктора firewall и оценка доступности трафика остаются
отдельным будущим продуктом, а не результатом этого изменения.
