## Границы данных

По согласованной политике адреса выделенного сервера записываются на логический
интерфейс `Selectel allocations`, если адрес ещё не занят. Один адрес может стать
Primary; это учёт выделения провайдером, а не доказательство физического интерфейса
или адреса гипервизора. Существующий Primary и чужие назначения сохраняются. У ранее заведённой
VM существующие интерфейсы не переименовываются и не присваиваются провайдеру
по одному имени. Совпавший частный IP без области сети не служит автопривязкой.

VRF новых облачных сетей изолированы по ID сети и области провайдера; это не
утверждение, что между ними отсутствует маршрутизация. Полученная топология
роутеров хранится отдельно. Изменённый вручную собственный компонент не
перезаписывается; при удалении аккаунта конфликт показывается до удаления.
Исчезновение компонента при неполном сборе не удаляет старую запись.

## Приёмка после обновления

1. Собрать оба аккаунта. Проверить `identityclub.ru`, `identityconf.ru`, `mgate`
   и Siena: карточка либо конкретная причина отказа, без выдуманной зоны.
2. На WAF/time-prod проверить интерфейсы, IP, Primary и диски. Повторить сбор:
   ID карточек/компонентов и существующий Primary должны сохраниться.
3. Проверить QA PAM/Build Agent: однозначные кандидаты связываются; неоднозначные
   остаются для ручного выбора с объяснением. WAN pfSense не переносится на ESXi.
4. Открыть оба глобальных роутера, найти адрес внутри подсети, проверить VLAN,
   CIDR, шлюз и служебные адреса; скрытые UUID остаются доступны модели/API.
5. Удалить и подключить аккаунт дважды. Сверить отсутствие дублей и сохранность
   прежних ESXi/Proxmox, чужих интерфейсов/IP и данных другого аккаунта.

Данные будущего конструктора firewall и оценка доступности трафика остаются
отдельным будущим продуктом, а не результатом этого изменения.

## Исправления после проверки PR #138

NetBox 4.7 ObjectView возвращает готовый HttpResponse. Поэтому добавление панелей
через process_template_response не работало на настоящей странице, хотя отдельный
тест шаблона проходил. Теперь используется отдельный layout экземпляра view до
отрисовки. Общий DeviceView.layout не меняется. Нативный сценарий проверяет GET
Device через Django Client, права доступа, расположение всех IP сразу под
Management и аппаратную конфигурацию как с Selectel, так и только с фактами хоста.
Кластеры, Site/Region, штатная вкладка VM и удалённые старые панели не меняются.

`NetBox Sync → Сети Selectel` показывает отдельные колонки имени, типа, аккаунта,
проекта и площадки. Типы «Глобальный роутер» и «Облачная сеть» разделены фильтром.
Это обзор существующих VRF; он не объединяет их и не меняет области адресов.
Идентификаторы и native-имена VRF сохраняются. Роутеры относятся к Tenant
«Глобальный роутинг» внутри группы аккаунта, облачные сети — к Tenant проекта.
Обновляются только неизменённые собственные объекты; ручная tenancy сохраняется.
Старый общий Tenant переименовывается только при доказанном создании интеграцией
и сохранении прежнего автоматического имени.

Глобальный поиск сохраняет форму, права, режимы и пагинацию NetBox. Полный IP/CIDR
сортируется перед содержащими подсетями, маршрутами и текстовыми совпадениями.
В режимах partial/exact дополнительно показываются отдельные строки маршрутов:
название, CIDR, следующий узел, роутер, аккаунт. Ссылка открывает карточку маршрута.
При выборе типов объектов маршруты доступны через VRF; regex/starts/ends работают
как штатный поиск. Маршруты не создают фиктивных подключённых Prefix.

Проверка на тесте после обновления:

1. Device AM Demo Cloud: три IP сразу под Management; аппаратная конфигурация ниже.
2. Device инфраструктурного сервера: CPU/RAM из хоста, физические диски отдельно;
   datastore не превращаются в физические диски. При отсутствии данных их не выдумывать.
3. Поиск `10.78.12.1`: точный IP выше `.125`/`.129`; поиск `10.160.0.0/16`:
   PAM-DEV-CLOUD, следующий узел и прямая ссылка на маршрут видны в результатах.
4. Обзор сетей: фильтр аккаунта и типа; переход в роутер или native VRF.
5. Повторный «Собрать и обновить» обновляет tenancy собственных VRF. IPAM ID,
   существующий Primary, ручные назначения и размещение остаются прежними.
6. CIDR/шлюз/служебные IP стоят в одинаковых колонках во всех сетях роутера.

Utilization в IPAM означает занятость учтённого адресного пространства, а не трафик.
Children — вложенные префиксы; число IP — записи IPAM, а не найденные в сети узлы.

## Оформление после приёмки PR #139

Аппаратный блок Device разделён на секции процессора, памяти и физических дисков.
Память хоста переводится из МиБ в ГиБ только при отображении, с точностью до двух
знаков; исходные значения и сведения о модулях Selectel сохраняются. Тип, количество
и объём каждого диска показаны отдельными колонками. Datastore не подменяет диски.

Фильтры обзора сетей переносятся на следующую строку при нехватке ширины.
Обе страницы роутера (ресурсы провайдера и native VRF) разделены на вкладки
«Сети и подсети» и «Статические маршруты» со счётчиками. Каждая сеть оформлена
карточкой с подписями названия, VLAN и площадки. Переключение вкладок сохраняет
параметры URL, а поиск только по маршрутам автоматически открывает их вкладку.
Прямая ссылка из глобального поиска по-прежнему открывает конкретный маршрут.

Повторный блок маршрутизации убран с VLAN. Штатные поля и Prefixes сохранены;
шлюзы и служебные IP доступны на подсетях и в IPAM. На странице самого VRF
повторная строка имени роутера/аккаунта не выводится. Ссылки с подсети/IP на
родительский роутер остаются.

Приёмка: AM Demo Cloud и инфраструктурный сервер №2 — секции и единицы памяти;
обзор сетей — кнопка «Применить» в окне обычной и малой ширины; grouter1/2 —
переключение вкладок и поиск маршрута; VLAN 1368 — штатные Prefixes без нижнего
повтора. Порядок IP, назначения, tenancy и размещение этим изменением не меняются.
