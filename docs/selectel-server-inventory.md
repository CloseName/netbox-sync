# Selectel: серверный импорт на тестовом NetBox

Этот этап расширяет уже принятые постоянные привязки. Production не обновляется.
UI подключения аккаунтов и расписание Selectel — следующий этап. Существующие
опросы ESXi/Proxmox продолжают работать независимо.

## Данные и их назначение

| Раздел | Выделенный сервер | Облачная VM |
| --- | --- | --- |
| Идентичность | Аккаунт + UUID ресурса; проект как принадлежность | Аккаунт + проект + регион + UUID VM |
| Конфигурация | CPU, RAM, диски, плата, корпус, GPU/PCIe/OCP, доступные serial/service tag | Flavor, vCPU, RAM, локальный диск, подключённые тома и их снимки |
| Размещение | Идентификатор и имя площадки, например SPB-3 | Регион и `OS-EXT-AZ:availability_zone` |
| ОС | Шаблон установки, версия, архитектура, RAID/разметка и адреса из boot/os | Метаданные образа; образ загрузочного тома хранится в разделе томов |
| Сеть | Выданные публичные/частные IP, подсети, VLAN, сети, физические порты по hw_uuid | NIC/MAC, fixed IP, floating IP, подсети, сети, маршрутизаторы, доступные security groups |

Коллектор `--profile servers` не опрашивает S3, DNS и остальные несвязанные продукты.
IAM-проекты нужны для перечисления облачных серверов и разграничения идентичностей;
пользователей аккаунта и биллинг в поля NetBox не импортируем. Общие каталоги образов
и flavors — справочники, а не количество принадлежащих аккаунту серверов.

API отдаёт данные в пределах прав. Даже HTTP 200 не доказывает, что учётная запись
видит все проекты аккаунта. В предпросмотре каждый раздел имеет статус:

- `collected`: выбранные данные получены;
- `empty`: успешно прочитанная коллекция не содержит связанных объектов;
- `not_reported`: ответ есть, но нужное значение отсутствует;
- `access_denied`: HTTP 401/403; это не отсутствие ресурса;
- `unavailable`: HTTP 404; недоступный endpoint/объект, не доказательство удаления;
- `not_collected`: этого раздела нет в файле;
- `partial`/`error`: неполная выборка, конфликтующие ответы или ошибка зависимости.

При недоступном разделе сохраняются последние полученные данные и их исходное
время `data_observed_at`; новая попытка имеет отдельное `observed_at` и `retained=true`.
Отсутствующие в новом файле серверы сохраняются в реестре и перечисляются как
`missing_retained`. Старый снимок не может откатить более свежий.

Пароли, ключи, user-data, пользовательские скрипты и произвольные metadata не
попадают в проекцию. Ответ boot/os фильтруется до сохранения и построения перечня
полей. Этот API может возвращать конфигурацию первоначальной установки, которая
не доказывает, какая ОС сейчас работает после самостоятельной переустановки.

## Владение и защита

Миграция 0008 создаёт `ProviderInventory` (включая ещё не сопоставленные серверы)
и журнал импортов. Post-migrate автоматически создаёт поля для Device/VM:

- `selectel_inventory`: полный нормализованный JSON, скрытый в стандартной карточке;
- `selectel_location`, `selectel_configuration`, `selectel_os`,
  `selectel_networks`, `selectel_collection_status`: видимые сводки;
- существующие `selectel_refs`, `selectel_summary` сохраняются.

Подробности доступны через API объекта в `custom_fields.selectel_inventory` либо
через Django shell. UI для реестра и связей пока отсутствует. Запись реестра без
связи не создаёт новый Device/VM. Это позволяет собрать весь видимый серверный
инвентарь без дублирования уже заведённых гипервизоров.

Импорт записывает только поля Selectel на объектах с принятой Guard-привязкой.
Существующие name, site, cluster, primary IP, native serial, интерфейсы, гостевые VM,
история и sync_identities остаются прежними. Поля гипервизора CPU/RAM не заменяются
провайдерскими: фактическая конфигурация и заказанная конфигурация видны раздельно.
Provider SQL guard защищает новые поля даже от обычного bulk/ORM/API обновления.
При ошибке одного объекта весь импорт откатывается, включая реестр и журнал.

Провайдерская площадка не преобразуется автоматически в NetBox Site, а выданный
IP не назначается вслепую на management-интерфейс. Наличие IP у сервера может
обозначать адрес гостевого firewall. NAT, физические кабели и межпровайдерская
топология не выводятся из совпадения адреса или подсети. Преобразование этих
наблюдений в native IPAM/DCIM требует отдельной модели подтверждённых связей.

## Запуск

На **netbox-test**, из проверенного commit:

```bash
bash /path/to/repo/deploy/update-selectel-test.sh
bash /path/to/repo/deploy/collect-selectel-test.sh 29916 admin
```

Первый скрипт обновляет Guard в `/netbox-test`, выполняет миграции и проверяет
здоровье обоих контейнеров. Бэкап БД не создаёт. Проверяет hostname и compose root,
не меняет production, Sync или расписания. Повторный запуск не создаёт новые поля.

Второй собирает свежие серверные данные с IAM-токеном через скрытый ввод Docker TTY.
Токен не записывается в argv, переменные окружения или файл. Затем создаёт обзор
импорта и выводит путь к `apply.sh`. В обзоре проверить targets (для текущего теста
Device 28/29), наборы данных и причины недоступности. Запустить напечатанный
`apply.sh`; при потере ответа повторять именно его, сохраняя nonce.

Низкоуровневая команда, если аудит уже есть внутри контейнера:

```bash
docker exec netbox /opt/netbox/venv/bin/python /opt/netbox/netbox/manage.py \
  selectel_inventory --input /tmp/inventory.json --account 29916 --actor admin
```

По умолчанию только review. Для записи нужны `--apply --fingerprint <из review>
--nonce <UUID>`. Изменение снимка, привязок или состояния targets делает review
устаревшим. При наличии более позднего импорта старый файл отклоняется.
Повтор нового review/apply того же файла не обновляет объекты и не повышает revision.

Для второго аккаунта выполнить отдельный сбор с его номером. Несопоставленные
серверы останутся в реестре. IAM-токен временный; автоматическое обновление
аутентификации сервисного пользователя и расписание требуют отдельной настройки.

## Проверка результата

На Device 28 и 29 появятся сводки Selectel, а данные NetBox Sync сохранятся.
После следующего опроса гипервизоров сводки не должны исчезать. Повторный импорт
того же файла должен вернуть `registry_updated: 0`, `targets_updated: []`.
Действующие protection claims проверяются изолированным CI с NetBox 4.7/PostgreSQL,
включая попытки подделки новых полей, откат, cloud VM, stale review и replay.

Документация API: https://docs.selectel.ru/api/dedicated/ — чтение resource/info,
location, сетевых объектов и GET boot/os. Полнота отдельных ответов проверяется
по фактической выгрузке, а не предполагается из наличия endpoint в документации.
