# Оставшиеся доработки и приёмка NetBox Sync

Обновлено 6 октября 2026. Выполненные пункты убраны из рабочего списка; исходные требования и результаты сохранены в [истории](requirements-history-2026-10-06.md). Реализация в коде не означает развёртывание или проверку на production.

## Проверки после обновления тестовой установки

- **REQ-014:** построить новый план PVE-INFRA-TEST. Для crm-bpm / net0 проверить замену Primary MAC с BC:24:11:2B:65:F3 на фактический MAC источника, затем ручной и scheduled-запуски и повторный план без изменений. Новая логика проверена автоматически; конкретный инцидент на установке ещё не закрыт.
- **REQ-011:** проверить массовые расписания и удаление на тестовых источниках с настоящими Guard-зависимостями. Локальные браузерные проверки подтверждения, отмены, частичного отказа и области выбора прошли. Реальные ресурсы ради теста не удалялись.
- **REQ-012:** проверить вложенные вкладки на снимке PVE-INFRA-TEST, обе темы и узкий экран. Некликабельность кнопок была только на production: повторить проверку там после обновления. Причина старого production-сбоя не доказана.
- **REQ-013:** после обычной синхронизации и обновления снимка проверить LAN/CIDR, поиск занятого IP, DHCP-пул, адрес вне сетей и кандидата. Сверить сеть VM по bridge/VLAN, не только по имени. Резервирование по-прежнему отложено; существующие резервы сохранены.
- **VirtualDisk и связи:** проверить родительский Device и отдельные диски VM на ESXi и Proxmox. Подготовить поле sync_disk_identity и проверить права токена на VirtualDisk. Чужие диски и назначения не заменяются автоматически.
- **Сбор PF/NAT:** обновить сборщик pfSense установленной процедурой и выполнить новый сбор. Старый снимок корректно показывает «не собиралось»; обновление одного Guard не обновляет удалённый сборщик.

Порядок обновления и контракт данных: [infrastructure-api.md](infrastructure-api.md).

## Ранее отложенная приёмка

- **REQ-001:** новый ESXi/Proxmox с отсутствующими справочниками — ждёт подходящего хоста. Не помечать пройденным по уже заполненному каталогу.
- **REQ-007:** фактические Weekly/Monthly и сохранность расписания после перезапуска службы. В текущем прогоне подтверждён запуск scheduler; успешное применение PVE блокировалось старым конфликтом MAC.
- Перенос описания VM повторно не тестировать: пользователь подтвердил, что давно работает.

## REQ-010: согласованный следующий этап после проверки

Пользователь отдельно подтвердил 6 октября 2026: Map и анализатор делать следующим этапом после проверки обновления на тестовой установке.

Общий слой чтения, API v1, связи Device–VM–NIC, просмотр сетей и всех собранных правил реализованы. Открыты следующие части архитектурного направления; они **не объявляются выполненными**:

- Подтверждение общей сети между разными гипервизорами по явным данным общей сетевой инфраструктуры. Совпадения bridge/IP/MAC для этого недостаточно; текущая версия не выдумывает такую связь.
- Сбор и разбор вложенных PF anchors и содержимого динамических таблиц. Top-level PF/NAT уже собираются, пробелы явно указаны в API.
- Объясняющий анализ пути, порядка firewall/NAT и расписаний; проверка сценария внутри LAN без pfSense. До появления такого анализа API не выдаёт выводы о разрешённом доступе.
- Будущая Map и сравнение сценариев без изменения реальной инфраструктуры — отдельный следующий этап [архитектурного решения](netbox-map-decisions.md).

Эти пункты оставлены видимыми, чтобы очистка списка выполненного не превратилась в потерю оставшихся требований.
