## Порядок установки

Сначала обновить **тестовый NetBox Guard**, затем **тестовый Sync** из одной версии ветки. Использовать существующие инструкции установки Guard в `deploy/netbox_guard/README.md`: сборка образа, миграции, перезапуск NetBox и его workers. При запуске миграций автоматически создаются два поля pfSense и согласуется отображение остальных совместимых полей. Несовместимые поля остаются без изменений с сообщением в журнале.

Перед обновлением проверить, что старая тестовая установка больше не запускает сбор под production-пользователем. Переключение режима не удаляет старые состояния и не переносит владельца чужой учётки.

При установке Sync добавить к существующему вызову `deploy/install.py`:

```text
--pfsense-user netbox-sync-test
```

Для production режим по умолчанию `netbox-sync`. В дальнейшем выбранный режим сохраняется установщиком. Старое тестовое подключение потребуется подготовить заново под отдельным пользователем; старый production-пользователь остаётся на pfSense.

Apply-пользователь NetBox должен иметь `view/add` для пяти общих справочников. Если их ещё нет, оператор NetBox один раз выполняет в контейнере NetBox (имя пользователя заменить, если оно другое):

```sh
/opt/netbox/venv/bin/python /opt/netbox/netbox/manage.py \
  configure_sync_catalog_permissions --user netbox-sync-apply
```

Команда работает только с существующим пользователем, не выдаёт `delete`, не расширяет права на устройства/VM и не меняет ограничения Guard. Импорт pfSense использует уже настроенное право изменения выбранной VM. Выдавать себе дополнительные права через Apply Token приложение не может.

После обновления коллектора повторить `Set up and collect` для принадлежащей этой установке учётки: это обновляет файлы сборщика, сохраняя её пароль и ключ. Обычный `Collect now` сам файлы на pfSense не обновляет.

## Правила расписания

- Интервальный режим сохраняет прежнее поведение: интервал от последнего scheduled-запуска; новый источник без такого запуска доступен сразу.
- Календарный режим использует сохранённое время изменения расписания для первого запуска. Перезапуск службы эту точку не меняет.
- После простоя выполняется один пропущенный запуск, следующие — по календарю; серия пропущенных запусков не воспроизводится.
- Если выбранного числа нет в месяце, используется последний день месяца.
- Действующая блокировка синхронизации не допускает два одновременных применения одного источника.
- Интерфейс предупреждает, если время ответа сервера отличается от часов браузера более чем на две минуты. Это сравнение часов, а не независимое подтверждение исправности NTP. На сервере проверить `timedatectl show -p NTPSynchronized --value`; системное время приложение не меняет.

## Пилот IPAM

1. В NetBox создать/проверить Prefix с правильной VRF. Для резервирования в VRF включить `Enforce unique`; для Global требуется `ENFORCE_GLOBAL_UNIQUE`. Иначе резервирование отключено.
2. Выполнить свежий сбор pfSense. Открыть Device/Cluster → «Сети» и один раз подтвердить конкретный интерфейс pfSense и Prefix/VRF. Нужны права просмотра и изменения выбранной подсети. Не объединять независимые LAN из-за совпадения имён/IP/MAC.
3. Открыть подсеть. Она определяется маской LAN, а не размером DHCP-пула. Учитываются native IPAM во всей VRF, диапазоны, шлюз/VIP, DHCP-пулы, привязки, аренды, ARP и спорные гостевые адреса в контексте кластера/VRF.
4. Проверить статический адрес за пределами DHCP-пула, адрес внутри пула, шлюз, известную VM и отсутствующий адрес. Последний обозначается **кандидатом**, а не гарантированно свободным.
5. Выбрать адрес-кандидат, указать описание и нажать «Зарезервировать IP». Требуется `ipam.add_ipaddress`, включая ограничения на создаваемый объект. Создаётся IPv4 `/32` со статусом Reserved; DHCP и гостевая ОС не меняются.
6. Повторить запрос и попытаться выбрать тот же IP в другом окне. Дубликат не должен появиться. Отдельно проверить штатную форму и API NetBox.
7. Остановить сбор дольше двух интервалов. Новые резервы должны блокироваться, ранее обнаруженные адреса — оставаться видимыми.

Границы пилота:

- Резервирование реализовано для IPv4, pfSense CE 2.7.2 и ISC DHCP leases. Неизвестный backend, ошибка чтения, неподдержанный proxy-ARP диапазон или неполный снимок дают «недостаточно данных», без выдачи адресов. Поддержка Kea leases не заявляется.
- Отсутствие ARP и истечение аренды не освобождают ранее наблюдавшийся адрес: он остаётся историческим наблюдением. Подтверждённую очистку таких записей администратор выполняет отдельно; автоматического удаления нет.
- Адреса из остальных кластеров учитываются через общую подтверждённую VRF/native IPAM. Неподтверждённые связи порт-групп не угадываются.
- Shared lock охватывает Guard, штатные операции REST IPAM и HTML-формы IPAddress. Прямой SQL и сторонние скрипты, обходящие валидацию NetBox, этой гарантией не охватываются.
- Наличие привязки сети может остановить Guard-retirement как неизвестная/внешняя зависимость. Это требует проверки администратором, а не автоматического удаления сети или резервов.
- Список выбора Prefix ограничен первыми 500 доступными объектами; пилот рассчитан на небольшой каталог. Глобальный поиск остаётся штатным поиском NetBox, подробный поиск адресов и кандидатов доступен внутри выбранной сети.
