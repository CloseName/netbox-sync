# Временная статистика NetBox PROD

Только NetBox, только авторизованные пользователи. Отдельный opt-in модуль, не включён в обычный образ Sync/Guard. Без изменений базы данных. Установка добавляет временный конфигурационный файл, middleware через уже установленный Guard, два bind mounts для web/worker и cron отчёта каждые 15 минут. Существующие плагины и middleware сохраняются.

Установка рассчитана на подтверждённый сервер netbox: /netbox/containers, четыре Compose-файла, NetBox 4.7.0, Guard /opt/netbox-sync-guard. Требуется активный Debian cron и Python3 с данными Europe/Moscow. Кратковременно пересоздаёт web/worker. Образы, PostgreSQL, Valkey и Sync не меняются.

Распаковать пакет в /var/tmp/netbox-usage, запустить `bash /var/tmp/netbox-usage/install.sh </dev/null` от root. При ошибке не повторять автоматически: посмотреть вывод и состояние контейнеров. Ошибка установки вызывает попытку запуска прежней конфигурации без сборщика, но это не гарантия успешного восстановления сервиса.

Отчёт: /netbox/usage-data/usage-report.txt. Пересобрать немедленно: `flock -w 60 /run/netbox-usage-report.lock python3 /netbox/usage-collector/report.py --directory /netbox/usage-data`.

Вход: успешный Django user_logged_in, а не каждый запрос с существующей авторизацией. Просмотр: успешный GET HTML-страницы; повторная загрузка тоже считается. Поиск: успешная HTML-страница /search или с непустым q; это не число нажатий клавиш. AJAX, API, статические файлы и неавторизованные запросы исключены. Периоды активности: наблюдения с паузой не больше 30 минут, не измерение рабочего времени. Отчёт показывает только дни с событиями. Переименование пользователя сохраняет группировку по его ID. Автоматический клиент с пользовательской сессией может выглядеть как пользователь; счётчики не доказывают чтение человеком.

Хранятся ID и логин пользователя, время МСК, тип события и обобщённый раздел. Нет IP клиента, URL объектов, поискового текста, cookies, токенов, содержимого страниц. Отчёт и ежедневные JSONL доступны через root на сервере, не опубликованы в NetBox. Сообщить коллегам о временном сборе статистики использования сервиса.

Нет ограничения в месяц и автоматической даты удаления. Данные накапливаются ежедневно, отчёт пересобирается целиком каждые 15 минут. Расход места растёт с количеством запросов. Один короткий append на событие; сбой записи не прерывает NetBox, но теряет соответствующее событие и пишет предупреждение в журнал приложения. Проверять свежесть файлов, а не только наличие отчёта. Старый отчёт при сбое генератора остаётся на месте.

При следующем обновлении NetBox обязательно включать пятый файл `-f docker-compose.usage.yml` после четырёх обычных, либо сначала удалить сборщик. Иначе конфигурация будет ссылаться на отсутствующий модуль.

Удаление: `bash /var/tmp/netbox-usage/uninstall.sh </dev/null`. Удаляет cron, подключение middleware, mounts и установленный код; пересоздаёт web/worker с исходными четырьмя файлами. Финальный отчёт и ежедневные данные сохраняются в /netbox/usage-data. Пакет установщика в /var/tmp можно удалить отдельно после успешного завершения. Перезагрузка pfSense и изменения Sync не требуются.

Приёмка: войти тестовым пользователем; просмотреть VM и IPAM; выполнить поиск; обновить отчёт; проверить счётчики и МСК. Повторный просмотр без нового входа не увеличивает число входов. После удаления убедиться в healthy контейнерах и отсутствии новых JSONL-событий.

Локально проверены фильтрация запросов, отсутствие поискового текста/URL в событиях, независимость ответа от сбоя записи, переход даты МСК и группировка периодов. Реальная загрузка Django middleware в production проверяется установщиком; до запуска оператором не подтверждена.
